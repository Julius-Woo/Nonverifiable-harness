# A3: native RHO calibration and loop extension

P1.5 implements three separately labelled paths: **A3-native**, **A3-loop**,
and **C-TTS-A3-loop** (the C-TTS(A3) control). Native calibration is
infrastructure evidence, not pilot data. AD1 and AD7 remain pending study
ratifications; this task explicitly authorizes terra-low-8k and three proposals
for this calibration. No preregistration or decision file is changed.

The recipe is implemented in [a3.py](../evolution/a3.py), with
[operators](../evolution/a3_operators.py), [coreset selection](../evolution/a3_coreset.py),
and [control selection](../evolution/a3_control.py). The local source is
[RHO, Algorithm 1 and Sections 4.1–4.3](papers/RHO_2606.05922.txt).

| Component | RHO value | Implemented |
| --- | --- | --- |
| Coreset | k=10, greedy-MAP DPP | 10 of the 18 fixed search tasks |
| Difficulty/diversity | theta=.7, epsilon=.1 | Same; raw-score floor before max normalization, Section 4.1 |
| Embeddings | BAAI/bge-large-en-v1.5, 1024 dimensions | Azure EP8 text-embedding-3-large, 1024 dimensions, L2 (default); calibration used the explicit local BGE condition |
| Group solves | G=3 per selected task under h0 | 30 fresh original-harness solves per round |
| Reference | Algorithm 1 step 5: first group solve | Replicate 0, fixed before proposals, shared by all three candidates |
| Diagnosis | Self-validation plus qualitative self-consistency | Per-trajectory success/quality/issues; failures, disagreement causes, one improvement direction, severity [0,1] |
| Proposals | N=3 independent proposals | 3 fresh copies of the same incumbent; no proposal sees its peers |
| Candidate evaluation | One solve per candidate per coreset task | 30 solves when all proposals are valid |
| Ranking | Candidate A/reference B; integer A→B in [−10,10] | Same fixed order, negate and divide by 10; task mean in [−1,1] |
| Native acceptance | Highest S strictly >0 | Same; positive ties resolved by preassigned candidate ID |
| Native rounds | One | One; launcher rejects later rounds and pilot use |
| Loop | Not studied by native RHO | One recipe per iteration, fixed seed-selected coreset, fresh incumbent group/reference per round |
| Backbone | GPT-5.5/high for all operators | Manifest task model: gpt56terra, low, JSON, 8192 completion allowance, 24-call solver/proposer cap |

The DPP implementation performs incremental Gram–Schmidt on normalized,
difficulty-weighted embedding rows. The next row with maximum squared residual
maximizes the incremental determinant. Equal gains use a SHA-256 tie order
from the local seed and task ID; the default local seed is 1. Reordering input
rows cannot change selection. Rank-deficient residual ties use that same rule.
For the explicit `--embedding bge` reproduction, the official embedding revision is
`d4aa6901d3a41ba39fb536a557fa166f842b0e09`; the coreset artifact records model-file
hashes, runtime versions, fingerprints and all vectors. Its ONNX SHA-256 is
`69ed3f810d3b6d13f70dff9ca89966f39c0a0e877fb88211be7bcc070df2a2ce`.
The live calibration initially selected its coreset with this exact local paper
model. That choice differed from the requested Azure route and is retained as
a calibration deviation; its tasks were not reselected after outcomes existed.
CLS pooling, normalization and omission of a retrieval-query prefix follow the
[official BGE model card](https://huggingface.co/BAAI/bge-large-en-v1.5).

New A3-native and A3-loop manifests default to Azure EP8
`text-embedding-3-large`, with 1024 requested dimensions and host L2 normalization.
[The accounted embedding adapter](../evolution/a3_embeddings.py) shares the
transport receipts, quota limiter, durable call cap and phase/session guards.
It preserves input ordering via response indices and caches completed vectors
by frozen input/endpoint/model/dimension identity. The estimated input rate is
$0.13 per million tokens from the [official model page](https://developers.openai.com/api/docs/models/text-embedding-3-large);
this is an API-equivalent planning rate, not an Azure invoice.
The [real Azure compatibility audit](../runs/a3-native-260910/azure-embedding-audit.json)
embedded the same 18 frozen fingerprints after selection. Its DPP coreset
shares 9/10 tasks with BGE. It did not replace the native coreset or trigger
additional task solves, diagnoses, proposals or selection rankings.

All language-model requests use `AccountedBackend`, including the same task
model for the proposer (RHO Appendix D.2). Roles are `a3-resolve`,
`a3-diagnose` (difficulty and diagnosis, distinguished by operator identity),
`a3-rank`, and the additional explicit `a3-propose` tag. The ledger records
requests, responses, tokens, USD estimates, served-model identity and timing.
There are no CLI model calls. Azure embedding batches use `a3-diagnose` plus
`operation="embeddings"`; their receipts and cost are included. The local BGE
option has zero embedding API charges.

Native selection uses S>0 without anchors. A3-loop passes baseline 0 and the
winning signed preference to the existing acceptance path with
`SearchEvaluation(scale="signed_preference")`. The `improve` variant requires
strictly positive gain; the `anchor` variant additionally requires the existing
calibrated tau and the unchanged private oracle regression bound epsilon.
Missing ranking pairs make a candidate ineligible, with no reduced denominator.

Selection fitness and measurement are distinct. Selection averages the ten
pairs against that round's first group solves. Fresh incumbent measurement
covers all 18 search tasks, compared against a separate fixed seed reference
per task from the preprocessing rollouts. A3-loop archives fresh seed measurement
against the same reference at t=0 for H5. Each iteration also performs its
standard private incumbent sealed avg@2 measurement. Native calibration has
only the final incumbent sealed measurement, with no sealed t=0 or anchor
queries. The task-solving model sees each assigned task in an isolated solve;
no optimization operator sees sealed/anchor task content or any oracle result.

A3 scores are relative preferences, never probabilities of correctness.
Summaries label their scale and suppress preference-minus-pass gaps. A3 is
eligible for oracle regret and H2/H5 only, not H1/H3; positive preferences,
ties and losses retain their signed meanings. A fresh seed reference used for
measurement is not substituted for Algorithm 1's group reference in selection.

C-TTS(A3) retains the comparator's frozen seed, matches its actual per-task,
per-partition physical rollout allocation cumulatively, and preserves durable
replicate identities on resume. Each search/anchor pool uses its first seed
rollout as reference; sealed evaluation has two disjoint parity pools, each
with its own first reference. The reference scores zero; other samples receive
the same signed pairwise self-preference. Highest score wins per task/pool,
with rollout-ID tie breaking. Held-out control scoring is isolated from
optimization, and its inputs/results remain in private archives. Additional
ranker costs are reported rather than claimed equal to evolution's total USD.

Evidence and failure handling:

The generic judge/sanitizer underwent a concurrent v3 migration after native
calibration started. A3 deliberately freezes the original v2 implementation in
[a3_v2.py](../evolution/a3_v2.py), including its typed envelope and exporter.
The running native controller had already imported the same original v2 code.
Its full-evidence exports remain v2; subsequent A3 runs use the compatibility
module. This does not authorize a v3 A3 condition. The checkout changed during calibration. The original manifest digest stays
frozen; `runtime-revision-1` and `runtime-revision-2` archive the controllers
used after the documented repairs, and the final audit separately hashes the
current checkout. These digests are not claimed identical. Paid prompts and
evidence remain archived under their actual dispatch hashes.

- Model inputs use complete `sanitized-trajectory-v2` exports and trusted
  termination metadata. Trusted trial rows, labels, result paths and partition
  metadata are never serialized into operator prompts.
- Both editable harness sources and their diff pass linewise through the same
  v2 sanitizer. Immutable host/accounting plumbing is omitted from ranker
  evidence. Proposal workspaces mount only their own writable candidate and
  their round's read-only diagnosis/trace archive; network access is disabled.
- Inline/workspace routing is deterministic from full serialized size. Full
  v2 files remain available during workspace inspection, including the 52 MB
  preprocessing trace observed in this calibration. Only task/trajectory/
  harness/diff evidence is mounted; there is no feedback or private-results mount.
- Operator inputs and attempt counts are durable. Completed results are reused;
  changed evidence fails on resume. A ranker failure gets one same-evidence
  retry, then rejects the candidate under the uniform A9 policy. Missing trace
  evidence fails closed before dispatch. Interrupted proposals are not silently
  resampled, and the independent-evolver recovery path is refused for A3. Rollout/infrastructure/grader retry policy is inherited unchanged.
- Host-enforced phase/session/rollout budgets and request reservations survive
  restarts. Four Harbor admissions and MemAvailable >=6 GiB protect the host.

Deviations and ambiguities are explicit:

1. The model, effort, JSON-in-text agent, editable Python-only surface, isolation,
   18/6/6 split and avg@2 sealed measurement belong to this project. RHO uses
   GPT-5.5/high, a broader files/tools/skills surface and its own TB2 split.
   This reproduces the recipe, not the paper's headline result.
2. Section 4.1's raw difficulty floor is used. Table 6 calls the floor normalized,
   while Appendix B.2 mentions division by ten. Common scalar normalization
   cannot change fixed-cardinality ordering; floor placement can.
3. The difficulty judge uses Appendix B.2's head/tail digest: 10,000 evidence
   BPE tokens plus an explicit elision marker, using `cl100k_base` (the paper
   does not pin the tokenizer). Scrubbing precedes digesting. The complete
   v2 export and digest provenance are retained. Digests are selector inputs
   only; they never replace diagnosis or ranking trajectories.
4. Prompts adapt Appendix B's filesystem language to structured v2 evidence.
   Diagnosis/ranking use JSON calls for inline evidence up to 60,000 bytes;
   larger inputs use a read-only inspection workspace with the same complete
   v2 files. This follows Appendix B's workspace inspection pattern. The model
   chooses spans/queries; oversized tool outputs are refused, never silently
   excerpted. Inspection permits 12 calls per attempt, 24 total with the A9
   retry, a 300-second attempt limit and a shared $5 scope cap. The proposer
   edits files using the existing containerized tool loop. It sees diagnoses, prompts and full
   motivating traces, resolving B.4/D.2 in favor of D.2's broader allowlist.
   Recorded traces do not reconstruct unrecorded workspace file contents.
5. Proposal sessions run sequentially on fresh copies for bounded resource use;
   RHO launches them in parallel. Solves and read-only operators use at most
   four concurrent calls instead of RHO's ten (cap thirty). Sampling seeds are
   local identity/tie-break seeds, not supported provider RNG controls.
6. RHO Appendix D.3 maps rank failures to zero without retry. The study's A9
   retry-once, then ineligible policy takes precedence. Source scans/import
   checks and finite host caps also belong to the common experimental runtime.
7. A3-loop, its optional anchor gate, fixed full-search H5 reference and
   C-TTS(A3) are study extensions, not native RHO claims. Native does not add
   ordinary-arm smoke or fresh avg@2 promotion solves to Algorithm 1.
8. The Azure default substitutes a different embedding model while retaining
   the DPP formula, difficulty weights, dimension and seed. The completed
   native task calibration uses the earlier BGE condition; the Azure embedding
   API/selector audit is not an end-to-end Azure-native performance calibration.

Run the native calibration from this checkout:

```bash
uv pip install tiktoken
uv run python -m evolution.a3_native --experiment a3-native-next
# Optional exact-paper embedding model:
uv pip install numpy onnxruntime huggingface-hub
uv run python -m evolution.a3_native --experiment a3-native-bge --embedding bge
# An interrupted run must keep its frozen manifest, embedding choice and budget:
uv run python -m evolution.a3_native --experiment a3-native-next --resume
# Read the completed historical calibration without new calls:
uv run python -m evolution.a3_native --experiment a3-native-260910 --resume
uv run python -m evolution.a3_report --experiment a3-native-260910
uv run pytest -q
```

versions and embedding file hashes are recorded with the coreset.
